# ASSIGNMENT 04 - Distributed Matrix Multiplication

## 1. Overview

The objective of this assignment is to study the performance of distributed matrix multiplication using **Dask Distributed**.

The implementation divides matrix multiplication into independent tasks that can be executed by different workers. The results are then collected and combined to reconstruct the final matrix.

The distributed implementation is compared with the sequential and parallel implementations developed in previous assignments.

The experiment focuses on understanding the overhead introduced by distributed execution, including task preparation, submission, computation and result collection.

## 2. Implementation

### Distributed Matrix Multiplication

The distributed implementation uses a **row-based partitioning strategy**:

1. Matrix A is divided into several row blocks.
2. Each task receives one block of A and the complete matrix B.
3. Each worker computes the corresponding block of the resulting matrix C.
4. The partial results are collected and combined to reconstruct the final matrix.

Each worker uses the same triple-loop (i-j-k) multiplication algorithm as the previous implementations.

The computation uses:
- Python
- NumPy (`float64` matrices)
- Numba (`@njit`)
- Dask Distributed

The local Dask cluster uses separate worker processes, with one thread per worker.

**Note:** All workers run locally on the same computer. Therefore, the experiment measures local distributed execution overhead rather than communication between physical machines.

## 6. Timing Measurements

The distributed implementation records several timing components:

- **Setup time:** Time required to create the local Dask cluster.
- **Distribution time:** Time spent preparing the matrix blocks locally.
- **Submission time:** Time required to submit tasks to Dask.
- **Gather time:** Time spent waiting for task completion and collecting the results.
- **Operation time:** Total time for the distributed multiplication operation, including block preparation, task submission, computation and result reconstruction.

Cluster setup is measured separately and excluded from operation time.

The sequential and parallel implementations measure only the multiplication kernel. Therefore, their timings do not have exactly the same measurement boundary as the distributed implementation.

## 7. Results and Observations

The experiments show that parallel execution with Numba improves performance compared with the sequential implementation for the tested matrix sizes.

The distributed implementation introduces additional overhead due to task management and result collection. Increasing the number of workers does not always improve execution time, particularly for smaller matrices.

These results illustrate that distributed execution is not automatically faster than sequential or shared-memory parallel execution. Its effectiveness depends on the workload size and the overhead associated with coordinating the tasks.

## 8. Correctness and Reproducibility

The final experiment contains **200 measurements**, with five repetitions for each tested configuration.

All recorded measurements passed the correctness validation, and the checksums were consistent across the implementations for each matrix size.

The raw measurements, statistical summary, environment information and generated plots are included in the `data/` directory to support reproducibility.
